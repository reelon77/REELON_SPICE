## 一、任务目标

把当前只支持单次 `.op/.tran` 的调用链扩展为可复用的直流扫描：

```text
.dc 网表
  -> 类型安全的 DcSweepAnalysis
  -> 按唯一器件名定位独立 V/I 源
  -> 为每个扫描点创建调用局部的源值覆盖
  -> Newton 求工作点，成功点作为下一点初值
  -> 结构化 DcSweepResult
  -> CSV / CLI
```
M09 不只是增加 `for` 循环。它必须同时建立后续 `.ac`、PULSE/SIN/PWL 和模型曲线所需的分析请求与独立源扩展点，并保证重复仿真、异常和扫描都不会修改 `const Circuit`。

## 二、任务范围

### 必须完成

1. 将分析配置收敛为类型安全请求，覆盖现有 `.op/.tran` 和新增 `.dc`，禁止产生“类型是 Op 但同时携带有效 tran/dc 字段”的状态。
2. `Circuit` 保存与 `devices` 一一对应的规范化器件名；所有器件名大小写不敏感且必须唯一。
3. 建立独立源公共抽象，使 V/I 源可以生成“只改变 DC 值”的调用局部副本；不得修改原 Circuit 中的源。
4. parser 支持：

   ```text
   .dc <source1> <start1> <stop1> <step1>
   .dc <source1> <start1> <stop1> <step1> <source2> <start2> <stop2> <step2>
   ```

5. source1/source2 只允许唯一存在的独立 V/I 源；两者不得相同。允许指令位于源定义之前，解析完成后统一解析引用。
6. 同一网表只允许一个 `.op/.tran/.dc`；重复或冲突分析指令必须带行号报错，不能沿用当前“后者覆盖前者”。
7. 支持升序和降序；step 不得为 0，符号必须指向 stop。使用整数步号生成值，避免反复累加漂移；不整除时只生成不越过 stop 的点。
8. 双源扫描采用 ngspice 语义：第二源为外层；每个 source2 值下完整扫描 source1。
9. 第一个扫描点使用全零初值，后续点使用结果序列中紧邻的成功点作为 Newton 初值；任一点失败则整体抛错，不返回伪完整或静默截断结果。
10. `SimulationResult`、writer 和 CLI 支持 DC 结果；CSV 列必须含一个或两个扫描量以及现有全部 `V(name)/I(name)`。
11. 添加单源、双源和降序 examples，并更新 README、回执、CMake 和 AI 台账。

### 明确不做

- 扫描电阻或 TEMP；三层以上扫描；list/dec/oct DC sweep。
- E/G/F/H、PULSE/SIN/PWL/AC 源表达。
- `.ac`、半导体新模型、`.model/.param/.include/.subckt`。
- 阻尼、limiting、失败缩步、并行扫描、流式超大结果。
- 安装 ngspice；当前机器未发现 ngspice，M09 以独立解析/手算 oracle 验收。

## 三、设计闸门

写生产代码前，任务会话必须在回执记录并锁定以下选择。

### D0-01：分析请求表示

必须比较：

- 继续扩展 `AnalysisType + t_step/t_stop + dc_*` 裸字段；
- 为每种分析建立具名 struct，并用 `std::variant` 表达唯一活动请求。

推荐第二种。允许为迁移保留只读兼容访问器，但不得维护两份可互相矛盾的状态；parser、controller 和测试最终必须以单一请求对象为准。

### D0-02：扫描源身份

必须锁定：

```text
device_names.size() == devices.size()
device_names 全部小写且全局唯一
dc.source_name -> 唯一 device index -> IndependentSource
```

不得使用 `branch_names` 查 current source，因为 I 源没有 MNA branch unknown；不得在 controller 重新解析原始网表。

### D0-03：非破坏式源覆盖

必须比较：

1. `const_cast`/setter 临时修改 Circuit 内源，再恢复；
2. 每点深拷贝整个 Circuit；
3. 只克隆被扫描的独立源，并在本点的非拥有 `Device*` 视图中替换该位置。

推荐方案 3。源副本由当前扫描调用拥有，裸指针不得逃逸；异常时依靠 RAII 自动清理。嵌套扫描同时覆盖两个不同源。

### D0-04：扫描序列与结果契约

推荐结构语义：

```text
DcSweepPoint {
  source_values: [source1] 或 [source1, source2]
  x
  newton_iterations
}

DcSweepAnalysisResult {
  source_names
  points                 // source2 外层、source1 内层的稳定顺序
}
```

CSV 推荐表头：

```text
sweep(v1),V(in),V(out),I(v1)
sweep(v1),sweep(v2),V(a),V(b),I(v1),I(v2)
```

具体类型名可调整，但公开结果不得依赖修改后的 Circuit 状态才能解释。

### D0-05：兼容与错误契约

- `.op/.tran` 的结构化结果与输出必须保持语义兼容。
- 错误至少区分：token 数、非法数值、零/反向 step、未知源、非独立源、重复源、重复器件名、冲突分析。
- 引用解析允许前向引用；错误包含 `.dc` 指令行和源名。
- 任一点求解失败向 CLI 传播为退出码 1，并指出扫描值或点序号。

绿灯：上述 5 项在回执形成最终接口草图、被拒方案和不变量；随后才能进入实现。

## 六、第 3 档：DC controller 与独立数值闸门

### 单电压源分压

```text
V1 in 0 0
R1 in out 1k
R2 out 0 1k
.dc V1 0 2 1
.end
```

独立 oracle：

```text
V1=0: [V(in), V(out), I(v1)] = [0, 0, 0]
V1=1: [1, 0.5, -0.5m]
V1=2: [2, 1.0, -1.0m]
```

### 单电流源与降序

用接地电阻和独立 I 源锁定电流方向、负节点电压和降序点顺序；oracle 必须由 KCL 手算，不可调用旧 solver 生成期望值。

### 双源嵌套

使用两个互不耦合的电压源和接地电阻，锁定“source2 外层、source1 内层”、两个 branch 电流以及四个扫描点的稳定顺序。

### 非线性连续性

增加 R-D-V 扫描，验证后一点使用前一点初值；数值正确性用二极管 KCL 残差和单点参考值共同判断，不把 Newton 自己的结果复制成 oracle。

绿灯：单源/双源/降序/非线性/失败传播全绿；原 `.op/.tran` 结果不变；更新 AI 台账；提交并推送。
