## 三、本任务目标

把网表文本变成 `Circuit`，完成最小可用 `.op` 语义解析：

- 指令：`.op` / `.end`。
- 器件：`R` / `V` / `I` / `D`，首字母判型，大小写已由 `tokenize` 归一化。
- 节点：任意字符串名称映射到连续整数；`0` 和 `gnd` 共享编号 0。
- 二极管：本阶段固定 `Is=1e-12`、`Vt=0.025852`，不解析 `.model`。
- 错误：未知器件/指令、token 数不对、数值解析失败均抛异常，消息包含网表行号。
- 分层：parser 只创建器件与 `Circuit`，**不 include / 不组装 `MnaSystem`**。

## 四、执行档位与绿灯

### 第 1 档：解析主循环 + `.op/.end`

- 推荐入口：接收 `std::istream&`，返回 `Circuit`；文件与测试分别可传 `ifstream` / `istringstream`。
- `getline` 逐行，维护从 1 开始的行号，每行调用 `tokenize`。
- 空 tokens 跳过；`.op` 设置 `AnalysisType::Op`；`.end` 终止读取。
- `.op/.end` 必须恰好只有 1 个 token；多余参数报错并带行号。
- 绿灯：注释 + 空行 + `.op` + `.end` 网表返回默认空电路；`.end` 后内容不处理。

### 第 2 档：节点名映射

- `0` / `gnd` 均返回 0，不增加新节点。
- 新名称按首次出现顺序获得 `1,2,...`；重复名称返回原编号。
- 必须单独维护 `next_node`，不能用 map 的 `size()` 推节点号，因为 `0` 与 `gnd` 是两个键却共享编号 0。
- 绿灯：`in/out/0/gnd/in` 映射为 `1/2/0/0/1`，最终 `Circuit.nodes == 3`。

### 第 3 档：器件行语义

| 首 token | token 数 | 参数语义 |
|---|---:|---|
| `r...` | 4 | name, node1, node2, resistance |
| `v...` | 4 | name, node_pos, node_neg, voltage |
| `i...` | 4 | name, node_from, node_to, current |
| `d...` | 3 | name, node_pos, node_neg（默认 Is/Vt） |

- `VoltageSource` 的 `sourceIndex` 按 V 器件出现顺序从 0 分配；每成功创建一个 V 再递增。
- 数值转换统一调用 `string2double`，不复制后缀逻辑。
- 器件用 `std::unique_ptr<Device>` 进入 `Circuit.devices`。
- 绿灯：四种器件各一例 + 未知首字母 + 参数数量错误 + 非法数值，所有错误包含行号。

### 第 4 档：两个网表端到端

1. `V1 1 0 10; R1 1 2 1k; R2 2 0 4k; .op; .end` → `v2 = 8V`。
2. `V1 1 0 5; R1 1 2 1k; D1 2 0; .op; .end` → `v2 = 0.574191503V`。

端到端可在测试中用 parser 返回的器件构造 `MnaSystem`，但 parser 本身仍不得依赖 MNA。

## 六、问题停车场（本任务不实现）

1. 行尾注释语法（`*` / `$` / `;`）及不同 SPICE 方言差异。
2. 电压源 `V1 1 0 DC 5` 的扩展形式。
3. `.model`、二极管模型名和参数。
4. `.dc` / `.tran` / 续行 `+` / 表达式与括号参数。
5. 节点原始名称的反向映射，用于未来 CLI 输出 `V(out)` 而不是只输出编号。
6. 缺失 `.end` 是允许 EOF 隐式结束，还是严格报错；在完整语法设计时统一决定。
