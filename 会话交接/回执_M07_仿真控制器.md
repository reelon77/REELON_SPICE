## 三、控制器形态与公开结果

最终选择无状态自由函数：

```cpp
SimulationResult simulate(const Circuit& circuit);
```

当前没有需要跨调用保存的配置、缓存或后端对象；自由函数使每次调用的工作区和借用关系清楚。
若未来出现稀疏结构缓存、续跑状态、多后端或持久诊断，再引入 `SimulationSession` 类；自由函数可继续作为兼容包装。

统一返回值为：

```text
OperatingPointResult { vector<double> x, int iterations }
TransientAnalysisResult { vector<TransientPoint> trajectory }
SimulationResult = variant<OperatingPointResult, TransientAnalysisResult>
```

`.op` 与 `.tran` 在类型层互斥；没有同时为空、同时有值或 tag 与 payload 冲突的无效状态。
controller 结果没有直接暴露 `NewtonResult`，避免公开应用层 API 与底层 solver 类型不必要耦合。

## 四、数据流与所有权

```text
const Circuit&（拥有 vector<unique_ptr<Device>>）
  -> 局部 vector<Device*>（只借用地址）
  -> 局部 MnaSystem（每次 simulate 新建）
  -> newton_solve / transient_solve
  -> 自己拥有 vector 数据的 SimulationResult
```

- controller 不 `move/release/delete` `Circuit` 中的器件。
- 裸指针视图不进入返回值、成员或静态缓存，不会逃逸本次调用。
- `MnaSystem` 只负责本次求解的 A/b 组装工作区，调用结束即销毁。
- `OperatingPointResult::x` 与轨迹中每个 `TransientPoint::x` 均自己拥有内存。
- solver 抛异常时局部对象自动清理，`Circuit` 所有权保持不变。

## 五、瞬态零初值策略

controller 创建：

```text
dim = (circuit.nodes - 1) + circuit.num_branch_unknowns
initial_x = vector<double>(dim, 0.0)
```

布局固定为 `[非地节点电压 | V/L 支路电流]`。它代表当前 MVP 的全零初态：电容初始端电压差为零，
电感初始支路电流为零，其余未知量也从零开始。

`t=0` 点直接记录该零向量，不是 Newton 求得的收敛点，也不是满足所有独立源约束的 DC 工作点。
`.ic`、`UIC` 和自动 DC operating-point initialization 继续留在停车场。

## 七、错误与重复调用契约

- 合法器件但没有分析指令时，`AnalysisType::None` 抛 `std::invalid_argument`。
- 未接地电阻形成奇异拉普拉斯矩阵时，LU 的 `std::runtime_error` 穿过 controller。
- 将已解析瞬态电路的 `t_step` 置零时，`transient_solve` 的 `std::invalid_argument` 穿过 controller。
- controller 不捕获异常后返回空 vector、默认 variant 或部分轨迹。
- 同一 RC `Circuit` 连续调用两次，时间和每个解分量逐项完全相同。
