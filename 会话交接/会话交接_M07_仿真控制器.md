## 一、任务目标

把已经存在但仍由测试手工拼接的链路：

```text
网表文本
  -> parse_circuit()
  -> Circuit
  -> 手工借用 Device* / 手工创建 MnaSystem / 手工选择 solver
```

收口为公开的仿真入口：

```text
网表文本
  -> parse_circuit()
  -> Circuit
  -> simulate(...)
       ├─ AnalysisType::Op   -> newton_solve()
       └─ AnalysisType::Tran -> transient_solve()
  -> 结构化结果
```

M07 的价值不是新增求解算法，而是建立稳定的应用层边界：后续 CLI、CSV 和 Python 画图只消费控制器，不再自行理解 MNA 维度、器件所有权或 solver 调度。

## 二、明确范围

### 本任务必须完成

1. 新建 `src/sim/` 仿真控制器模块。
2. 输入为已经解析完成的 `Circuit`；控制器不重复解析文本。
3. 根据 `Circuit::analysis_type` 调度 `.op` 或 `.tran`。
4. 控制器内部创建正确维度的 `MnaSystem`，并从 `Circuit::devices` 建立只在本次调用内有效的非拥有 `Device*` 视图。
5. `.op` 返回 Newton 工作点及迭代信息；`.tran` 返回包含 `t=0` 的轨迹。
6. 返回值必须是结构化 C++ 数据，不在核心模块里打印、写文件或格式化 CSV。
7. `AnalysisType::None` 必须明确拒绝，底层求解异常保持可观察，不能吞掉后返回伪结果。
8. parser → controller → solver 的 `.op`、RC `.tran`、RL `.tran` 集成测试全绿。

### 本任务明确不做

- `.dc`：当前没有 `AnalysisType::Dc`、扫描参数或 parser 语法，不能写空壳冒充支持。
- CLI 参数解析、终端打印、CSV、Python 画图。
- 节点名反向映射、支路名称和表头生成。
- `.ic`、`UIC`、先求 DC 工作点再启动瞬态。
- PULSE/SIN/PWL、变步长、梯形法、失败后缩步重试。
- 稀疏矩阵、ngspice 对拍、多线程扫描和可视化。

## 三、当前可复用接口

```text
Circuit
  devices: vector<unique_ptr<Device>>
  nodes: int                         // 含地节点
  num_branch_unknowns: int           // V/L 共用支路空间
  analysis_type: None / Op / Tran
  t_step, t_stop

MnaSystem(nodes, num_branch_unknowns)

newton_solve(devices, sys, ...)
  -> NewtonResult { x, iterations }

transient_solve(devices, sys, t_step, t_stop, initial_x, ...)
  -> vector<TransientPoint>          // 含 {t=0, initial_x}
```

必须复用这些实现；禁止在控制器里复制 stamp 遍历、Newton、LU 或时间步进循环。

## 五、第 0 档：控制器契约设计闸门（只读，不写实现）

开工前先画清以下数据流和生命周期：

```text
const Circuit&（拥有 unique_ptr<Device>）
  -> 本地 vector<Device*>（只借用，不转移所有权，不逃逸）
  -> 本地 MnaSystem（每次 simulate 新建）
  -> solver
  -> 自己拥有 vector 数据的结果对象
```

### 需要比较并由用户选择的三个问题

#### 1. 控制器形态

- 无状态自由函数 `simulate(const Circuit&, ...)`；
- 保存配置/缓存的 `SimulationController` 类。

当前推荐自由函数：现有 solver 都是无状态函数，目前没有可复用缓存或后端对象；以后真出现持久配置再升级成类。

#### 2. 统一返回值

- `std::variant`：`.op` 与 `.tran` 结果在类型层互斥，调用方必须按分支读取；
- 带 tag 的普通 struct：API 直观，但容易出现“Op 类型却同时装着 trajectory”等无效状态；
- 两个完全分开的公开函数：实现简单，但不能形成统一调度入口。

当前推荐“具名结果包装 + `std::variant`”，例如概念上：

```text
OperatingPointResult { NewtonResult ... }
TransientAnalysisResult { vector<TransientPoint> ... }
SimulationResult = variant<OperatingPointResult, TransientAnalysisResult>
```

这里只规定语义，不要求照抄字段名；用户必须先能解释为什么它比“两个可同时为空的 vector”更安全。

#### 3. 瞬态初始状态

M07 固定采用与 M06 parser 闭环相同的**全零初始解**：长度为

```text
(circuit.nodes - 1) + circuit.num_branch_unknowns
```

这代表“所有节点电压和支路电流从 0 开始”的最小策略，不等价于完整 SPICE 的 DC operating-point initialization。`.ic/UIC/DC-init` 留停车场。

### 第 0 档必须锁定的边界

1. `simulate` 接收 `const Circuit&`，不夺走器件所有权，也不保存裸指针。
2. `.op` 使用 `newton_solve`，即使电路全线性也不另开一套 LU 快捷路径。
3. `.tran` 只把 `Circuit::t_step/t_stop` 和零初值转交 `transient_solve`。
4. `None` 抛明确异常；solver 的奇异、不收敛和参数异常向上继续传播。
5. 控制器不打印、不读文件、不认识 CSV，也不负责把 x 下标翻译成节点名。

绿灯：用户能复述选择及代价，接口草图通过 review；此前不创建 `src/sim` 实现。

## 六、第 1 档：`.op` 调度（P0）

1. 新增控制器头/实现文件并挂入 `SpiceLib`。
2. 在一次调用的局部作用域内：
   - 从 `Circuit::devices` 借用 `Device*`；
   - 用 `nodes` 和 `num_branch_unknowns` 创建 `MnaSystem`；
   - 调用既有 `newton_solve`；
   - 返回拥有自身数据的工作点结果。
3. 不允许把裸指针视图作为返回值、成员或静态缓存。
4. 若第 0 档决定暴露 Newton 配置，至少保留当前默认值 `tol=1e-9`、`max_iter=300`，不要在多处复制不一致的默认值。

### 独立数值闸门

用 parsed `.op` 分压网表：

```text
V1 1 0 10
R1 1 2 1k
R2 2 0 4k
.op
.end
```

结果必须为：

```text
x = [10 V, 8 V, -2 mA]
```

另保留二极管工作点 `v2 ~= 0.574191503 V` 的集成覆盖，证明控制器没有误走线性专用路径。

绿灯：`.op` 两个闸门 + 原 116 个回归全绿；编号 review 清零；阶段提交。

## 七、第 2 档：`.tran` 调度（P1 主体）

1. 根据系统维度创建全零 `initial_x`。
2. 原样传入 `Circuit::t_step`、`Circuit::t_stop` 和 Newton 配置。
3. 返回完整轨迹，保持 M06 约定：第 0 点为 `{0.0, initial_x}`。
4. 不在控制器里复制整数步数规则、历史推进或 Newton 循环。

### RC 独立闸门

```text
V1 in 0 2
R1 in out 2
C1 out 0 500m
.tran 250m 500m
.end
```

`[vin, vout, iV]` 前两步：

```text
t=0.25: [2, 0.4,  -0.8]
t=0.50: [2, 0.72, -0.64]
```

### RL 独立闸门

L 故意写在 V 前，锁定共享 branch 顺序：

```text
L1 out 0 500m
V1 in 0 2
R1 in out 2
.tran 250m 500m
.end
```

`[vout, vin, iL, iV]` 前两步：

```text
t=0.25: [1,   2, 0.5,  -0.5]
t=0.50: [0.5, 2, 0.75, -0.75]
```

绿灯：RC/RL 从网表经 controller 得到上述独立结果；原回归全绿；编号 review 清零；阶段提交。
