## 三、下午：网表解析器（今天主菜）

### 目标

`src/parser/`，把文本网表变成器件对象。做完后这两个网表要端到端跑通（数值就是两块金标准，不用算新的）：

```
* 分压电路                      * 二极管电路
V1 1 0 10                      V1 1 0 5
R1 1 2 1k                      R1 1 2 1k
R2 2 0 4k                      D1 2 0
.op                            .op
.end                           .end
```

### 范围（最小可用集，明确不做的也列出）

- 器件行：`R` / `V` / `I` / `D`（首字母判型，大小写不敏感——SPICE 惯例全文件大小写不敏感）
- 二极管参数用默认值（Is=1e-12, Vt=0.025852），参数化模型（`.model`）**不做**
- 注释行 `*`、空行、`.op`、`.end`；`.dc`/`.tran` **不做**（指令的数据结构留好扩展位即可）
- 数值后缀（SPICE 标准倍率，大小写不敏感）：
  `f=1e-15, p=1e-12, n=1e-9, u=1e-6, m=1e-3, k=1e3, meg=1e6, g=1e9, t=1e12`
  **经典坑：`m` 是 milli 不是 Mega，Mega 要写 `meg`**——用户第一次见 SPICE 后缀，这个坑让他自己撞或自己查到，是好记忆点
- 节点名：字符串 → 连续编号的映射（`unordered_map`），`0` 和 `gnd` 都算地；网表里节点名可以是任意标识符（`in`、`out`），不只是数字——这是"节点名→编号映射"存在的意义
- 错误路径要做：未知器件字母、参数个数不对、数值解析失败——**报错带行号**，扔异常即可

### 设计引导（方向给到这，具体让用户设计）

1. **分层**：解析器产出"器件列表 + 节点数 + 电压源数 +指令"（一个 `Circuit` 聚合结构，所有权用 `unique_ptr<Device>`——多态容器的标准姿势，他第一次用智能指针容器的话是个好教学点），**parser 不 include MnaSystem**——它只造对象，不组装。分层试金石和昨天 solver 不 include Diode 同款。
2. **两段式**：先"行 → token 流"（纯字符串，独立可测），再"token → 器件"（语义层）。他 LSM-Tree 的经验在这直接用。
3. **一个必须想清楚的耦合点**：`VoltageSource` 构造要收"自己是第几个电压源"——parser 按出现顺序计数分配。这个约定要写进 Circuit 的注释。

### 单测建议（从小到大，每档一提交）

1. 数值解析单元测：`1k`→1000、`4.7u`、`1meg` vs `1m`（那个坑）、非法输入抛异常
2. 分词/注释/空行/大小写
3. 节点名映射：字符串名、`0`/`gnd` 同义、编号连续性
4. 器件行各型一例 + 错误路径（带行号断言）
5. 端到端 ×2：上面两个网表 → 组装 → 求解 → 8V / 0.574191503V（复用金标准断言）
