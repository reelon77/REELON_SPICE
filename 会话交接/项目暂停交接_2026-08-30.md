## 一、项目一句话定位

TinySpice 是一个使用 C++23 自主实现的、面向学习和求职展示的 SPICE3 实用子集：读取文本网表，通过器件 Stamp、MNA、LU、Newton-Raphson 和固定步长瞬态求解完成 `.op/.dc/.tran`，再输出结构化结果、文本或 CSV，并可交给 Python/MATLAB 消费。

项目不得描述成“完整兼容 SPICE/ngspice/PSPICE/HSPICE”，也不支持现代 PDK 的全部工业紧凑模型。正式 1.0 边界见 `docs/TinySpice_1.0_规格与路线图.md`。

## 二、当前构建产物：不是 DLL

当前 CMake 明确生成：

```cmake
add_library(SpiceLib STATIC ...)
add_library(TinySpiceCli STATIC ...)
add_executable(TinySpice ...)
```

因此当前产物是：

```text
SpiceLib       静态 C++ 仿真库
TinySpiceCli   静态 CLI 适配库
TinySpice      可执行程序
```

它们不是 Windows DLL，也不是 macOS `.dylib` 或 Linux `.so`。Go 分布式系统当前应通过子进程调用 `TinySpice` CLI，而不是通过 cgo 直接加载库。

若未来必须进程内调用，需要单独完成：

1. 在 C++ 外包一层稳定的 `extern "C"` ABI，不能直接暴露 `std::string`、`std::vector`、C++ 异常或多态对象；
2. 使用 `add_library(TinySpiceC SHARED ...)` 生成 Windows `.dll`、macOS `.dylib`、Linux `.so`；
3. 定义输入、输出、错误缓冲区、内存释放和 ABI 版本；
4. 在 Go 中用 cgo 包装 C ABI；
5. 加入跨语言生命周期、并发、错误和版本兼容测试。

第一版分布式联动仍推荐 CLI：隔离清晰、崩溃不污染 Worker、无需解决 C++ ABI 和跨语言内存所有权。

## 三、已完成能力

### 1. 数值与电路内核

- 稠密行优先 `Matrix`。
- 手写 LU 分解，包括教学用不选主元版本和正式部分选主元版本。
- 置换、前代、回代和奇异矩阵诊断。
- `MnaSystem` 统一处理地节点跳过、节点未知量和 V/L 支路未知量。
- `Device::stamp()` 多态器件装配。
- Newton-Raphson 非线性迭代与二极管 companion model。
- 电容、电感后向欧拉 companion model。
- 固定步长瞬态轨迹，历史状态只在成功步后推进。

### 2. 当前器件

- 电阻 R；
- 电容 C；
- 电感 L；
- 独立 DC 电压源 V；
- 独立 DC 电流源 I；
- 使用内置参数的二极管 D。

### 3. 当前分析

- `.op`：线性及当前二极管范围内的非线性直流工作点；
- `.tran <tstep> <tstop>`：全零初始状态、固定步长后向欧拉；
- `.dc <source> <start> <stop> <step> [source2 start stop step]`：单/双独立 V/I 源，支持升序、降序和前向引用，双源时 source2 外层。

M09 已把分析请求收敛为 `std::variant` 类型 IR；DC 每点只克隆被扫描的独立源，不修改 `const Circuit`，后续点延续上一成功解作为 Newton 初值。

### 4. Parser 与错误契约

- `istream` 逐行解析；
- 名称和指令大小写不敏感；
- 支持普通数值、科学计数法和常用 SPICE 工程后缀；
- `0/gnd` 统一地节点；
- 节点、器件和支路名称具有稳定顺序；
- 器件名称全局唯一；
- `.op/.dc/.tran` 只能出现一个，冲突带行号；
- 解析、扫描点、求解和输出错误通过异常传递至 CLI。

### 5. 输出与工具链

- `.op` 输出带 `V(node)`、`I(branch)` 和 Newton 迭代数的文本；
- `.tran` 输出 `time` + 电压/支路电流 CSV；
- `.dc` 输出一到两个 `sweep(source)` + 电压/支路电流 CSV；
- 数值使用 C locale 和可往返的 `double` 精度；
- Python `scripts/plot_transient.py` 用于跨平台绘图和无 matplotlib CSV 校验；
- MATLAB `scripts/plot_transient.m` 用于交互绘图或 PNG 导出；
- CLI `--matlab-plot` 会在瞬态 CSV 写入成功后自动执行 `matlab -batch`，无需手动打开 MATLAB。

## 四、真实调用链

```text
SPICE netlist
    ↓ tokenize / numeric
Circuit IR
    ↓ simulate(const Circuit&)
Device stamp → MNA
    ↓
LU / Newton / transient / DC sweep
    ↓
SimulationResult
    ↓
result_writer
    ↓
stdout / CSV
    ↓ 可选
Python 或 MATLAB batch
```

核心层不打印、不启动 MATLAB，也不依赖前端。MATLAB 自动化只存在于 `TinySpiceCli` 后处理层。

## 六、Go 分布式系统的当前联动方式

当前推荐每个 Worker 把一次完整仿真作为隔离任务：

```go
cmd := exec.Command(
    tinySpiceBinary,
    netlistPath,
    "-o", resultCsvPath,
)
combinedOutput, err := cmd.CombinedOutput()
```

若本地 Worker 明确安装 MATLAB，可以额外传入：

```go
"--matlab-plot", resultPngPath
```

分布式生产环境不建议让每个仿真 Worker 依赖 MATLAB。更合理的职责拆分是：

```text
Simulation Worker   运行 TinySpice，上传 CSV 和日志
Plot/Postprocess    可选消费 CSV，使用 Python 或 MATLAB
Dispatcher          lease、heartbeat、超时、重试、取消、幂等
Aggregator          按 job/shard/扫描坐标汇总结果
```

推荐任务身份包含：

```text
job_id + shard_id + engine_commit + netlist_hash + analysis_config
```

同一 Circuit 可以并行运行不同网表变体、参数、激励或完整分析。当前不要直接拆 `.tran` 时间点；单次 `.dc` 也优先作为完整任务，因为当前点序列使用上一成功点热启动。

## 十、当前明确限制

- 不是完整工业 SPICE；
- 没有 E/G/F/H 受控源；
- 没有 PULSE/SIN/PWL/AC 源；
- 没有 `.ac`；
- 没有 `.model`、BJT、JFET、MOS Level 1；
- 没有 `.param/.include/.subckt`；
- `.tran` 没有 DC-init、`.ic/UIC`、梯形法、变步长、阻尼和器件 limiting；
- 没有稀疏矩阵后端；
- 没有 ngspice 自动差分测试；
- CSV 不是流式写出，大轨迹会完整保存在内存；
- MATLAB 自动后处理只支持 `.tran`。
